[SPEC] 036 — Compare mode: 2–3 independent role-slot panels, one shared resume paste

*(Depends on spec 035, landed at `ecb46e0` — both touch `App.tsx`; not parallelizable with it.)*

- **Objective**: Add a "Compare roles" toggle to Step 1. Off (default): identical to today — one role picker, one `useRolePanel`/`RoleResultsPanel` instance, byte-identical accessible names to the current audited shape. On: reveal a second independent role picker (slot 1) immediately, plus a "+ Compare a third role" control that reveals a third (slot 2, max). Each active slot is its own always-mounted `useRolePanel` instance (3 calls, fixed, Rules-of-Hooks-safe) rendering its own `RoleResultsPanel`, laid out side by side in a new `.compare-grid` wrapper (wrapping to stacked on narrow viewports). **One shared resume textarea** feeds every active slot: submitting calls `submitResume(text)` on each active slot's own hook instance — one paste, up to 3 independently-scored comparisons. When 2+ slots are active, every per-slot `role="status"`/`role="alert"` element (in `App.tsx`'s per-slot picker area, and inside `RoleResultsPanel`/`FilterStatusBar`) gets its accessible name qualified with that slot's own role name, and each panel's rendered output is wrapped in a labelled landmark, so a screen-reader user can always tell which panel/slot they're in — this SPEC does not ship with the accessible-name collision spec 035 flagged as a forward-pointer.
- **Inputs/Outputs**:
  - **Slot wiring (fixes a real API mismatch found in the original draft)**: `App.tsx` holds `roleSlots: [string, string, string]` (display-only mirror of each `<select>`'s value; slot 0 is today's `selectedRole`, unchanged) and calls `useRolePanel(roleSlots[i])` exactly 3 times, unconditionally, at fixed call sites (`panels[0]`, `panels[1]`, `panels[2]`) — the initial argument is only ever consumed once per hook-instance-lifetime, per spec 035's documented `useState(initialValue)` contract. **Every role change for slot `i`** — the user picking a new option in that slot's own `<select>`, or "Clear saved data"/toggling compare mode off resetting a slot back to `''` — calls both `setRoleSlots(...)` (for the controlled `<select>`'s value) **and** `panels[i].loadRole(newRole)` (the side-effecting call that actually triggers `useRolePanel`'s internal refetch), in the same handler, mirroring `handleRoleChange`'s existing two-call pattern exactly. No slot's role ever changes by argument mutation alone.
  - **Compare state**: `compareMode: boolean` (new). Turning it off calls `panels[1].loadRole(''); panels[2].loadRole('')` and resets `roleSlots[1]/[2]` to `''` (explicit cleanup, not just "stop rendering" — avoids stale fetched data lingering in an unmounted-from-view-but-still-hook-mounted slot).
  - Each slot's own `<select>` disables `<option>`s already chosen in a sibling active slot, preventing picking the same role twice.
  - Layout: new `.compare-grid` wrapper (CSS grid, `auto-fit`/`minmax`, collapsing to one column under the existing mobile breakpoint) holding 1–3 landmark-wrapped `RoleResultsPanel` instances (see next bullet).
  - **Accessible-name qualification**: Every element identified as colliding across simultaneous panels gets an optional qualifier, applied **only when `compareMode` is `true`** — in `compareMode === false` (the default, already-audited single-panel path), every one of these stays byte-identical to today, verbatim:
    - `RoleResultsPanel` gets one new prop, `compareMode: boolean` (required, defaults to how `App.tsx`'s single-panel call site passes `false`). When `true`, its no-gaps status paragraph's `aria-label` becomes `` `Skill gap result — ${role}` `` (was `"Skill gap result"`), and it passes `roleName={role}` down to `FilterStatusBar`.
    - `FilterStatusBar` gets one new optional prop, `roleName?: string` (mirrors `SkillLeverageTable`'s existing `roleName` prop naming). When provided/non-empty, its root's `aria-label` becomes `` `Skill filter status — ${roleName}` `` (was `"Skill filter status"`). Omitted (the only other call site, none currently exists outside `RoleResultsPanel`) → unchanged base label.
    - `App.tsx`'s own three per-slot status elements, **only rendered with the suffix when `compareMode` is true** (identical unsuffixed markup otherwise): loading → `` `Loading skill profile — ${roleSlots[i]}` ``; empty-profile → `` `No skills found for this role — ${roleSlots[i]}` ``; error (`role="alert"`, which carries no locked `aria-label` today, so this is a **visible content** change, not an aria-label change) → `` `Could not load skill profile for ${roleSlots[i]}: ${panel.errorMessage}` `` (was `` `Could not load skill profile: ${errorMessage}` ``).
    - **Landmark wrapper (new, cheap, addresses a broader heading/button-text duplication issue also surfaced during this revision)**: each active slot's `RoleResultsPanel` output, inside `.compare-grid`, is wrapped in `<section aria-label={`${roleSlots[i]} comparison column`}>` — gives every screen-reader user a landmark to distinguish panels by role even where per-component headings (`SkillGroupBreakdown`'s "Which skill group is driving your score", `SkillMatrix`'s "Where each skill sits", etc.) repeat verbatim across panels. In `compareMode === false`, there is exactly one panel and no wrapper is added (nothing to disambiguate, and it would be one more unaudited DOM change for zero benefit).
- **Design Pattern**: none — simple case, reusing spec 035's already-isolated unit N times. `Simplicity > Pattern purity`.
- **Bounded-AI boundary**: Zero LLM. Each slot's numbers are computed exactly as spec 035 already guarantees, independently per slot — **no cross-role aggregate metric is computed or displayed here.** The new accessible-name qualification is plain string templating (`` `${base} — ${role}` ``) over data already in scope (the slot's own role string) — no new computation, scoring, or lookup.
- **Verification Oracle**:
  - `frontend/e2e/compare-roles.spec.ts` (new) `@ desktop-light`, `@ desktop-dark`, `@ mobile-touch-light`:
    1. **Layout**: toggling "Compare roles" on renders exactly 2 panel-level containers side by side (desktop) / stacked (mobile); "+ Compare a third role" adds a 3rd.
    2. **Data isolation**: stub two roles with deliberately distinct, diffable fixture skill names (slot-A stub contains `"alpha-only-skill"`, slot-B stub contains `"bravo-only-skill"`). Pick role A in slot 0, role B in slot 1, submit one shared resume, then rapidly re-pick slot 1 to a third role C before slot-1's fetch for B can plausibly resolve. Assert slot 0 never renders `"bravo-only-skill"` or C's marker skill, and slot 1 settles on C's data only — proving `loadRole` (not argument mutation) is actually wired per slot, closing the API-mismatch gap concretely, not just in prose.
    3. **Accessible-name distinctness**: with slots 0/1 both settled (role A / role B), assert `getByRole('status', { name: 'Skill filter status — <RoleA>' })` and `getByRole('status', { name: 'Skill filter status — <RoleB>' })` are each independently findable (two distinct elements, not one ambiguous match) — repeat for the no-gaps status name where applicable, and assert each panel's landmark `getByRole('region', { name: '<Role> comparison column' })` resolves to exactly one element per role. Delay slot 1's route fulfillment (`page.route` with an artificial delay, same technique `stubRoleSkillProfile` already supports extending) to also catch and assert the qualified `'Loading skill profile — <RoleB>'` name mid-flight.
    4. **Zero regression in default mode**: with `compareMode` off, assert `getByRole('status', { name: 'Skill filter status' })` (no suffix) still resolves exactly as today, and no `.compare-grid`/landmark wrapper exists in the DOM at all.
- **UI Scope**: structural — a new toggle, new slot pickers, a new multi-panel grid, and new landmark wrappers are real DOM/layout changes (Magnolia).
- **Intellectual Control**: The isolation guarantee itself is unchanged from spec 035 (per-instance closures); this SPEC's only new risk surface is (a) correctly wiring `loadRole` per slot instead of relying on argument reactivity, which the e2e oracle's rapid-re-pick assertion directly targets, and (b) the accessible-name qualification being purely additive and gated on `compareMode`, so the already-audited single-panel path (spec 035/037) is provably untouched when compare mode is off.
- **Constraints**: No new dependency. Persistence (spec 034) is **not** extended in this SPEC — slots 1/2 and the compare toggle are session-only and reset on reload; slot 0's existing persistence is unaffected. The accessible-name fix is verified at the e2e layer only (no new component-unit test file, e.g. no `FilterStatusBar.test.tsx` addition) — a deliberate, disclosed trade to stay within the 5-file cap; the e2e assertions are real, standing assertions against the actual rendered app, not a weaker substitute.
- **Edge Cases**: Turning compare mode off discards slots 1/2 state entirely via explicit `loadRole('')` calls (no "remember for next time" within this SPEC). Picking the same role already active in a sibling slot is prevented at the picker (disabled option), not detected post-hoc. Removing slot 2 collapses back to 2 panels; removing down to 1 is not offered — leaving compare mode via the toggle is the path back to a single panel. A slot's `role="alert"` error content changing wording only when `compareMode` is true means the exact same underlying error can render two different strings depending on mode — acceptable since it's not a locked-verbatim constant anywhere in the codebase today (confirmed by inspection), unlike `NO_GAPS_MESSAGE`.
- **Files** (5):
  1. `frontend/src/App.tsx` (edit: toggle, `roleSlots`, 3 fixed `useRolePanel` calls, per-slot `loadRole` wiring, per-slot status markup with `compareMode`-gated qualifiers, `.compare-grid` + landmark wrapper, fan-out submit) — Magnolia
  2. `frontend/src/components/matrix/RoleResultsPanel.tsx` (edit: new `compareMode` prop, qualified no-gaps `aria-label`, threads `roleName` to `FilterStatusBar`) — Magnolia
  3. `frontend/src/components/matrix/FilterStatusBar.tsx` (edit: new optional `roleName` prop, qualified `aria-label`) — Magnolia
  4. `frontend/src/components/matrix/matrix.css` (edit: `.compare-grid` responsive rules) — Magnolia
  5. `frontend/e2e/compare-roles.spec.ts` (new) — Cypress (red first)
- **Tipping Point**: If a 4th comparison slot or a persisted "saved comparison" concept is ever requested, reconsider `roleSlots` as an array-of-N rather than a fixed 3-tuple, and bump `localPersistence`'s storage key. If a 3rd class of per-panel duplicated content beyond headings/status regions is ever reported as confusing under a screen reader, stop qualifying labels one at a time (as spec 037 first did, and as this SPEC now does for a second round) and adopt a single shared `panelLabel`-suffixing convention/helper used by every component that can render more than once per page, rather than re-deriving the `` `${base} — ${role}` `` template ad hoc at each call site.
